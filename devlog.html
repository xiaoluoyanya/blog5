v7.0 Architecture 📅 2025-11-26

🛠️ v7.0：架构重构与位面同步

System Modularization

随着功能的不断增加，index.html 的代码量越来越多。为了避免“牵一发而动全身”的维护噩梦，v7.0 重点进行了底层架构的拆分与重组。

1. 架构重构：页面静态化 (Static Separation)

我们将原本臃肿的“优化笔记”弹窗从主页中剥离，建立独立的 devlog.html 页面。

  • 瘦身成功： 主页代码量减少了约 40%。
  • 扁平化管理： 采用同级目录结构，解决了相对路径导致的资源丢失（图片、CSS）问题。
  • 维护性： 现在更新日志有了专属领地，不再干扰主页的逻辑。

2. 状态同步：记忆植入 (State Sync)

为了解决“主页是黑夜，跳到笔记页变白天”的体验割裂感，我们引入了 LocalStorage 技术。

// 1. 主页切换时写入状态 localStorage.setItem('site_theme', 'dark'); // 2. 笔记页加载前读取状态 if(localStorage.getItem('site_theme') === 'dark') { ... }

现在，浏览器会记忆你的偏好。无论你在哪个页面切换日夜模式，整个网站的所有页面都会同步响应。

3. 视觉修复：无缝黑夜 (Infinite Dark)

修复了最为顽固的“背景白边”和“背景塌陷” BUG。

通过使用 CSS 高级选择器 html:has(body[data-theme="dark"]) 和 background-attachment: fixed，我们将星空背景强制钉死在视口底层，彻底消灭了滚动条边缘和页面底部的白色漏光，实现了真正的沉浸式体验。

4. 扩展性：万能模板系统

确立了未来的更新规范：

  • 系列更新： 继续在 devlog.html 中通过版本切换展示。
  • 独立文章： 创建了 template.html 标准模板，未来撰写单篇游戏评测或技术博客时，只需“复制-粘贴-修改”，即可快速生成新页面。

Architecture Stabilized.

v6.0 Major Update 📅 2025-11-25

🚀 v6.0：从静态主页升级为动态主页

Project: Transformer Profile

这是一个里程碑式的版本。经过高强度开发与代码迭代，终于将个人主页从一个静态的展示页，升级为具有动态叙事能力的互动网页。

1. 核心特效：动态形态变换 (The Morphing)

这是本次更新最困难、也最酷炫的功能。左侧的个人信息栏现在拥有两种形态：

  • 初始形态： 一个占据屏幕 90% 宽度的 Hero Banner（大横幅），极具视觉冲击力。
  • 最终形态： 随着滚动条下滑，它会平滑收缩、归位，变成标准的 300px 侧边栏。

为了解决动画过程中的“视觉抖动”和“内容拉伸”问题，采用了坐标系锁定技术：

// 关键逻辑：焊死高度 + 左上角坐标系修正 leftCol.style.height = "650px"; // 物理锁死高度 leftCol.style.transformOrigin = "0 0"; // 钉死左上角

2. 沉浸式体验升级

为了让网页更有质感，我们对视觉细节进行了全方位打磨：

  • 黑夜模式 2.0 修复了网页两侧的白边问题，现在背景是纯粹的深邃黑，配合星空粒子，沉浸感拉满。
  • 布局重构 重新规划了右侧作品集的顺序（博客 ➡ 相册 ➡ 游戏），更符合浏览逻辑。
  • 顶部导航 新增了磨砂玻璃质感的顶部 Navbar，整合了“一键回城”和“功能开关”。

3. 全新的“优化笔记”系统

你现在看到的这个页面就是本次更新的成果之一！

  • 独立阅读页： 采用了左侧目录、右侧内容的经典博客布局。
  • 版本控制： 左侧新增了版本切换功能，可以随时回顾 v5.0、v4.0 的开发历程。
  • 访问计数器： 基于 LocalStorage 实现了访问量统计

4. 交互优化

加入了“一键通关”逻辑：点击首页按钮，会自动触发开场动画并丝滑滚动到底部，直接展示网页的“完全体”形态。

v5.0 Connectivity 📅 2025-11-24

⚡ v5.0：域名加速与邮件集成

Connection Established

在这一版本中，我们暂时放缓了视觉特效的开发，转而专注于解决网站的“可用性”和“连接性”问题。无论是联系方式的便捷性，还是网页的加载速度，都是用户体验的核心。

1. 邮件交互优化 (Mailto Protocol)

为了简化访客联系我的流程，我对左下角的“发送邮件”按钮进行了原生协议绑定。

改进前： 用户需要手动复制邮箱地址，切换应用发送。

改进后： 利用 mailto: 协议，点击按钮即可直接唤起系统默认的邮件客户端（如 Outlook, Mail App），并自动填好收件人地址。

<a href="mailto:xx@qq.com"> ✉️ 发送邮件 / Email </a>

2. 域名绑定与访问加速

本站托管于 GitHub Pages。虽然稳定，但由于服务器位于海外，国内网络环境下经常遇到加载缓慢甚至无法打开的情况。

为了彻底解决访问速度问题，我执行了以下操作：

  • 注册独立域名： 购买并注册了专属域名
  • 域名验证： 完成阿里云的认证后才可以修改默认DNS
  • DNS 解析配置： 在域名服务商处添加 CNAME 记录，将其指向 GitHub 的源地址。
  • 仓库绑定： 在 GitHub 仓库设置中开启 Custom Domain，完成握手验证。

经过一系列配置，现在国内访客可以通过新域名享受到更快的响应速度，无需再忍受龟速加载。

v4.0 Functionality 📅 2025-11-23

⚡ v4.0：功能觉醒 - 留言板实装与音频系统重构

System Online

如果说前几个版本是在“装修房子”，那么 v4.0 就是在“接通水电”。在这一版中，我们让静态的网页拥有了真正的数据交互能力和复杂的媒体控制逻辑。

1. 留言板实装：从“装饰”到“通讯”

在旧版本中，留言板只是一个本地的 UI 玩具，刷新页面后数据就会消失。为了实现真正的匿名留言功能，我引入了 Serverless 方案。

  • 技术选型： 接入了 Formspree API 服务。
  • 实现方式： 使用 JavaScript 的 fetch() 方法拦截表单提交，实现了 AJAX 无刷新发送。

现在，访客在留言板提交的信息会直接推送到我的个人邮箱，实现了真正的即时通讯。

// AJAX 核心逻辑 fetch("https://formspree.io/f/xxxx", { method: "POST", body: data, headers: { 'Accept': 'application/json' } }).then(...)

2. BGM 按钮交互反馈优化

修复了一个存在的问题：右上角的 BGM 按钮。之前点击按钮虽然能切歌，但 UI 上永远显示 "OFF"。

优化后： 加入了状态监听。当音乐播放时，按钮会变色并显示 🎵 ON；暂停时变回灰白色 OFF。操作反馈更加直观。

3. 独立播放器与音频互斥逻辑

本版新增了一个功能强大的“内置音乐播放器”，包含专辑封面、切歌控制和播放列表。

但这也带来了新问题：如果 BGM 和播放器同时响，声音会打架。为此我编写了一套音频互斥（Audio Mutex）逻辑：

if (player.play()) { // 当播放器开始时，强制关掉全局 BGM bgm.pause(); updateBgmButtonState("OFF"); }

现在，当你点开播放器的一瞬间，背景音乐会自动静音让路，享受纯净的听歌体验。

v3.0 Atmosphere 📅 2025-11-22

🎨 v3.0：初具雏形 - 氛围感与基础框架

Setting the Mood

在搭建好基本的 HTML 骨架后，v3.0 的重点在于赋予网页“灵魂”。通过加入音乐和光影变化，让访问者进入网页时能感受到独特的个人风格。

1. 背景音乐 (BGM) 实装

网页不再是静默的。我利用 HTML5 的 <audio> 标签引入了背景音乐功能。

  • 自动/手动播放： 考虑到浏览器策略，虽然设置了自动播放，但增加了手动开关按钮。
  • 循环播放： 添加了 loop 属性，确保音乐不会中断。

2. 日夜模式切换 (Day/Night Toggle)

为了增加互动性和视觉层次，我制作了一套“黑夜模式”的 CSS 样式。

点击右上角的切换按钮，通过 JS 修改 body 的类名，从而触发 CSS 变量的改变（如背景色、文字颜色），实现一键从清新的白天切换到深邃的黑夜。

3. 留言板 UI 框架搭建

在这个版本中，我设计并实现了一个侧滑式留言板的 UI 界面。

  • 交互方式： 点击悬浮按钮，留言板从屏幕右侧滑出。
  • 功能现状： 暂未实装 目前仅完成了前端界面的搭建（输入框、发送按钮），点击发送后暂时只能在本地模拟效果，尚未接入后端通讯服务。

虽然还不能真的发邮件，但这个漂亮的侧滑抽屉为 v4.0 的功能实装打下了坚实的基础。

v2.0 Content & Performance 📅 2025-11-21

📦 v2.0：内容填充 - 内容实装与资源本地化

Assets Loaded

有了 v1.0 的 HTML 骨架后，v2.0 的主要任务是“装修”。我为网站填充了具体的个性化内容，并在开发过程中发现了严重的加载延迟问题，通过“本地化策略”成功解决了它。

1. 内容填充与丰富

  • 游戏收藏 (Collection)： 添加了一些游戏封面。
  • 模型库 (Inventory)： 准备了一些 GLB 模型文件。
  • 作品集 (Portfolio)： 上传了一些图片。

2. 3D 引擎代码优化 (Model Viewer)

为了在网页上展示 3D 模型，我使用了 Google 的 <model-viewer> 组件。

问题： 最初直接引用了 Google 的 CDN 链接，导致每次刷新都要去请求远程服务器，一旦网络波动，模型就无法加载。

优化： 我将核心 JS 库 model-viewer.min.js 下载至项目本地进行引用。这不仅减少了 DNS 解析时间，还保证了离线开发时的稳定性。

<!-- 优化前：依赖远程 CDN --> <script src="https://ajax.googleapis.com/.../model-viewer.min.js"></script> <!-- 优化后：本地直接加载，飞快！ --> <script src="./model-viewer.min.js"></script>

3. 资源路径优化 (Local Assets)

在填充图片和模型时，我最初尝试直接链接 GitHub 仓库里的文件地址。

遭遇瓶颈： 发现图片加载极其缓慢，这是因为 GitHub 的原始文件服务器在国外，且对直链流量有限制。

解决方案： 放弃远程引用，改用相对路径 (Relative Path)。我将所有图片放入 images/ 文件夹，模型放入 3d model/ 文件夹，直接读取本地文件。

background-image: url('images/绫小路.jpg');

v1.0 Genesis 📅 2025-11-20

🌱 v1.0：起源 - Hello World 与 独特构想

Hello World

这是梦开始的地方。在浏览了市面上无数千篇一律的 Bootstrap 模板和 WordPress 主题后，我决定抛弃所有现成的轮子，从零开始写第一行代码，打造一个完全属于我的、独一无二的数字秘密基地。

1. 拒绝模板：游戏化 UI 设计理念

我想让它看起来有趣点。受到 RPG 游戏的启发，我构思了一种“玩家属性面板”风格的视觉语言：

  • 角色卡： 头像不是简单的照片，而是带有 HP（精力）和 MP（灵感）条的玩家状态栏。
  • 背包栏： 展示技能和模型的地方，被称为“Inventory”。
  • 任务书： 博客和项目经历，被设计成“已解密的任务档案”。

2. 架构核心：三栏式布局 (The Grid)

为了容纳这些丰富的信息，我确定了市面很少主页模板使用的“左-中-右”三栏结构

#main-dashboard { display: grid; /* 左侧 300px | 中间自适应 | 右侧 340px */ grid-template-columns: 300px 1fr 340px; gap: 25px; }

这种布局既稳定又灵活，左侧固定展示个人信息，右侧固定展示作品入口，中间则是流动的核心内容区。

3. 技术选型与地基搭建

作为第一版，虽然没有复杂的交互，但扎实的框架得搭建好的：

  • HTML5 语义化标签： 使用 <aside>, <main>, <nav> 而非全是 div。
  • CSS3 变量系统： 在 :root 中定义了 --primary-red, --sky-blue 等主题色，为之后要添加的日夜切换打下基础。
  • 字体美学： 引入了 Google Fonts 的 Fredoka One（圆润标题）和 Nunito。
  • Flexbox & Grid： 混合使用两大布局利器，实现了卡片内部的完美居中。
